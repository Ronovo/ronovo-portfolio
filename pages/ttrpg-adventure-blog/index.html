Publish solo TTRPG play straight from Obsidian

An Obsidian overlay for publishing solo tabletop RPG play. You keep writing in your vault as usual, and it turns that vault into a website without changing how you write.

What it does

It has two halves: an admin panel you keep to yourself, and a public site you show to readers.

Admin panel

A dashboard of the vault, a preview, a "what changed" view and publishing. It has no login, so it only listens on your own machine or a private network such as Tailscale.

Public site

Read-only static pages with no logins, forms or admin routes. This is the only half readers ever see.

Publish when ready

Nothing in the vault goes live until you publish it. Later edits never touch the live version until you publish again.

Campaigns and sessions

Campaign pages list their sessions grouped by arc. Every session gets previous and next links and a "Previously on..." box with the last session's recap.

A wiki that builds itself

Characters, NPCs, places, factions, items and quests list every post that links to them, and readers filter the wiki by game and type.

Story mode

One switch hides the dice, oracles, sheets and notes so readers can follow just the story, with a panel to choose what stays.

Themes

Readers pick Original, Light, Dark, Cyberpunk, Eldritch or Fantasy, and the choice is remembered in their browser.

RSS feeds

A site-wide feed, plus one for each campaign.

Writing in Obsidian

The vault is plain Markdown, so any editor can write it. Obsidian is recommended, because the site runs on the same tagging Obsidian already understands.

What drives the site

  • Properties such as type, campaign, session and tags decide what kind of page a file is, where it lives and how it is filed.
  • [[Wiki links]] and ![[embeds]] connect sessions, campaigns and wiki entries.
  • Callouts such as > [!oracle], > [!roll] and > [!card] mark solo mechanics, and the site turns them into styled blocks.
  • Templates insert a ready-made page of each type.

Solo mechanics blocks

> [!oracle] Is the guard awake?
> Odds: Likely
> Roll: 72
> Result: Yes, but...
> He's groggy. I'll have a round before he raises the alarm.
  • [!oracle], [!roll] and [!table] for questions, dice and table results.
  • [!card] for tarot or playing card draws: a single card, a hand or a sequence.
  • [!sheet] for a snapshot of a character's stats. The character's wiki page shows the latest one and how it changed over time.

How publishing works

  1. Write or edit in Obsidian. Your sync, such as Obsidian Sync, delivers the change to the server.
  2. The admin notices it. The Updates page shows the page as Draft or Unpublished changes.
  3. Tick one or more pages, then Review & publish. The review shows what changed and warns about links to pages that aren't live.
  4. Publish takes a snapshot of each page and rebuilds the site once.

Along the way

  • Deleting a file is a pending change. The page stays live until you publish the deletion.
  • Renaming or moving a file keeps the same page. If its web address changes, the old one redirects.
  • Preview builds the whole vault, drafts included, before anything goes live.
  • Every published version is kept, and any of them can be restored into the vault.

Run it

Requires Node.js 20.12 or newer.

From source

npm install
cp .env.example .env
npm start

Set VAULT_DIR in .env to your Obsidian vault, then open the admin panel at http://localhost:8081. The public site is at http://localhost:8080.

On a server

deploy/ holds a Docker Compose stack: the public site, plus the admin panel bound to a private address, reading the vault from a folder on the server. Its README covers setup and getting your vault onto the server.

Keep the admin private

The admin panel has no login. Never put it on the internet. A reverse proxy or tunnel that puts the site online points only at the public site's port.
