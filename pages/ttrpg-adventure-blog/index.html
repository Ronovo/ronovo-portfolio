What it does

Two halves: an admin panel you keep to yourself, and a public site you show to readers.

  • Admin panel

    A dashboard of the vault, a preview, a "what changed" view and publishing. It has no login, so it listens only on your own machine or a private network such as Tailscale.

  • Public site

    Read-only static pages with no logins, forms or admin routes. The only half readers ever see.

  • Publish when ready

    Nothing goes live until you publish it, and later edits never touch the live version until you publish again.

  • Campaigns, sessions and a wiki

    Campaign pages list sessions by arc, each with previous and next links and a "Previously on..." recap. Characters, NPCs, places, factions, items and quests list every post that links to them.

  • Story mode

    One switch hides the dice, oracles, sheets and notes so readers can follow just the story, with a panel to choose what stays.

  • Themes and feeds

    Readers pick Original, Light, Dark, Cyberpunk, Eldritch or Fantasy, remembered in their browser, and get a site-wide RSS feed plus one per campaign.

Writing in Obsidian

The vault is plain Markdown, so any editor can write it. Obsidian is recommended, because the site runs on the same tagging Obsidian already understands.

Properties
type, campaign, session and tags decide what kind of page a file is, where it lives and how it is filed. Set type:, or put the file in a folder such as Play Reports or NPCs.
Links
[[Wiki links]] and ![[embeds]] connect sessions, campaigns and wiki entries.
Callouts
> [!oracle], > [!roll], > [!table] and > [!card] mark solo mechanics and become styled blocks. [!sheet] snapshots a character's stats, and the character's wiki page shows the latest one and how it changed.
Templates
Insert a ready-made page of each type.

How publishing works

  1. Write or edit in Obsidian. Your sync, such as Obsidian Sync, delivers the change to the server.
  2. The admin notices it. The Updates page shows the page as Draft or Unpublished changes.
  3. Tick one or more pages, then Review & publish. The review shows what changed and warns about links to pages that aren't live.
  4. Publish takes a snapshot of each page and rebuilds the site once.
Along the way
Deleting
A pending change. The page stays live until you publish the deletion.
Renaming
Keeps the same page. If its web address changes, the old one redirects.
Preview
Builds the whole vault, drafts included, before anything goes live.
History
Every published version is kept, and any of them can be restored into the vault.

Run it

Requires Node.js 20.12 or newer. The admin panel has no login: never put it on the internet. A reverse proxy or tunnel that puts the site online points only at the public site's port.

npm install
cp .env.example .env
npm start

Set VAULT_DIR in .env to your Obsidian vault, then open the admin panel at http://localhost:8081. The public site is at http://localhost:8080.

On a server

deploy/ holds a Docker Compose stack: the public site, plus the admin panel bound to a private address, reading the vault from a folder on the server. Its README covers setup and getting your vault onto the server.
