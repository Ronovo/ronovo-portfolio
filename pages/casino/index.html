Ronovo's Casino

A repo for learning how to program casino games, played in the browser. One person runs the server; anyone on the network can log in and play.

Horse racing

The stable

Every horse in Data/horses.json has a rating, a preferred trip (sprinter or stayer), a preferred surface (firm or mud) and a running style. Each race draws a distance and a going.

Real odds

A horse runs to its strength on the day plus random luck. The luck is Gumbel-distributed, which makes the chance of every finishing order exactly calculable, so the prices on the board come from real probabilities less the house margin (margin in the table file).

Seasons

A season is 40 races. Points are 10/5/3/1 for the first four; the standings are shown before and after every race, and the leader after race 40 is champion.

Handicapping

A horse that wins with 2 or more wins in its last 8 runs carries 6 lb more (up to 30 lb), and each pound costs half a rating point. A weighted horse sheds 1 lb for every finish outside the first three. All of these numbers are in Data/Tables/09_horse_racing.json.

Accounts and characters

  • Each player creates an account (username and password) on the login page, and picks a security question. Passwords and answers are stored as salted PBKDF2 hashes, and a login lasts 30 days per browser.
  • Forgot password? resets the password with the security answer and logs the account out everywhere. Five wrong answers lock resets for 15 minutes.
  • An account holds up to 8 characters. Each character has its own chips, record, achievements and racing season.
  • Characters saved before accounts existed belong to nobody. Register an account, then hand one over: python main.py --claim "Ronovo Ronove" your_username
  • The server uses plain HTTP, which is fine on a home network. To open it to the internet, put it behind an HTTPS reverse proxy.

Log in with a portfolio account

With PORTFOLIO_SSO_URL (the portfolio's address) and PORTFOLIO_SSO_PUBLIC_KEY (printed by the portfolio's python sso.py) set, the login page offers to log in with a portfolio account. It reads Log in as and the portfolio username when this browser is logged in to the portfolio. The first portfolio login here asks whether to link a casino account the player already has, by logging in to it once, or to make a new one named after the portfolio username, with a number added if that name is taken. Every later portfolio login from any device opens the linked account.

A new account has no password of its own, so the portfolio is the only way into it. Without those two settings the app runs on its own.

Run it

How to run

  1. Install Python 3.10 or newer (no extra packages needed).
  2. From a terminal: python main.py
  3. Open the address it prints. http://localhost:8000 on your own computer; other players use the "For other players" address (your computer's address on the local network). Windows may ask once to allow Python through the firewall.
python main.py --port 8080          # a different port
python main.py --host 127.0.0.1     # private: only this computer can connect
python main.py --verbose            # log every request

Saves

Progress lives in casino.db next to main.py (set the CASINO_DB environment variable to use another file).

Older databases upgrade automatically on launch: characters, chips and achievements are kept.

For developers

Tests

python -m unittest discover -s Tests -t .

Game rules are pure functions (casino/rules). Full rounds are played through each game's start/act interface with stacked decks (Tests/test_games.py), thousands of random rounds check that no credit is ever created or lost (Tests/test_soak.py), and EDGE_CASES.md lists what that turned up.

Adding a table (new scenario, no code)

Copy a file in Data/Tables, change key, title, order, limits, settings and paytable. It appears on the casino floor the next time the server starts.

Adding a game

  1. Put the rules as pure functions in casino/rules/<game>.py and unit test them.
  2. In casino/games/<game>.py, subclass Round (what happens after the bets are down: actions, perform, table_view, staked) and Game (rules_pages, paytable, and start, which validates the bets with read_stake, takes them with take_stakes and returns the round). Pay out with settle and end the round with finish.
  3. Register the class in casino/games/__init__.py and add a table JSON with "game": "<game_key>".
  4. Add casino/web/static/js/games/<game>.js exporting render(ctx, mount) and list it in GAMES in js/app.js.
