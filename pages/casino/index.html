The tables

Each table is a JSON file in Data/Tables, and several tables can share one game engine. Around them: accounts, achievements, per-game win and loss records, a chip exchange, and a fresh start for broke characters.

Horse racing

  • The stable

    Every horse in Data/horses.json has a rating, a preferred trip and surface, and a running style. Each race draws a distance and a going.

  • Real odds

    A horse runs to its strength plus Gumbel-distributed luck, which makes every finishing order exactly calculable, so the board prices are real probabilities less the house margin.

  • Seasons

    40 races; points are 10/5/3/1 for the first four, standings before and after every race, and a champion after race 40.

  • Handicapping

    A winner with 2 or more wins in its last 8 runs carries 6 lb more (up to 30 lb), each pound costing half a rating point, and sheds 1 lb per finish outside the first three.

Accounts and characters

Sign-up
A username, a password and a security question. Passwords and answers are stored as salted PBKDF2 hashes, and a login lasts 30 days per browser. At most 20 accounts can be made in any 10 minutes.
Characters
An account holds up to 8 characters, each with its own chips, record, achievements and racing season.
Forgot password
Resets the password with the security answer and logs the account out everywhere. Five wrong answers lock resets for 15 minutes, and a question can't be changed once set.
Lockouts
Five wrong passwords in a row lock a username's logins for a minute. Usernames are public: registering says when one is taken, and the reset says when there is no such account.
On the internet
The server speaks plain HTTP, fine on a home network. To expose it, put it behind an HTTPS reverse proxy and set SECURE_COOKIES=1.
Log in with a portfolio account

With PORTFOLIO_SSO_URL and PORTFOLIO_SSO_PUBLIC_KEY set, the login page offers to log in with a portfolio account, and reads Log in as plus the portfolio username when this browser is logged in there. The first such login links a casino account you already have, or makes a new one named after the portfolio username.

A new account has no password of its own, so the portfolio is the only way into it. Without those two settings the app runs on its own.

Run it

Requires Python 3.10 or newer. Windows may ask once to allow Python through the firewall.

pip install -r requirements.txt
python main.py

Open the address it prints: http://localhost:8000 on your own computer, or the "For other players" address for the rest of the network. --port 8080 picks another port, --host 127.0.0.1 keeps it private, --verbose logs every request.

Saves

Progress lives in casino.db next to main.py. Set the CASINO_DB environment variable to use another file.

Tests 
python -m unittest discover -s Tests -t .

Game rules are pure functions in casino/rules. Full rounds run through each game's start/act interface with stacked decks, thousands of random rounds check that no credit is ever created or lost (CASINO_SOAK=1), and the edge cases that turned up are kept. The browser client's tests live in Tests/js; both suites cover every line and branch.

Adding a table or a game

A table needs no code. Copy a file in Data/Tables, change key, title, order, limits, settings and paytable. It appears on the floor the next time the server starts.

A game is four steps: put the rules as pure functions in casino/rules/<game>.py and unit test them; in casino/games/<game>.py subclass Round (actions, perform, table_view) and Game (rules_pages, paytable, start), taking later bets with take, paying with settle and ending with finish; register the class in casino/games/__init__.py with a table JSON naming it; and add casino/web/static/js/games/<game>.js exporting render(ctx, mount), listed in GAMES in js/app.js.
